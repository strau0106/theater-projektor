# infmk1 — backup target and remote access hub

`infmk1` is a Linux server (Debian/Ubuntu) reachable from the internet. The projector
connects *out* to it (it never needs an open port itself, so it works behind any
venue NAT / guest WiFi):

| Purpose | User on infmk1 | Key on the projector | Restriction (authorized_keys) |
|---|---|---|---|
| Reverse tunnel (SSH + web UI of the projector) | `projtunnel` | `/var/lib/projektor/.ssh/id_tunnel` | `restrict,port-forwarding,permitlisten="127.0.0.1:2222",permitlisten="127.0.0.1:8080",command="/bin/false"` |
| Backup / restore of media + show | `projbackup` | `/var/lib/projektor/.ssh/id_backup` | `restrict,command="rrsync /srv/theater-projektor"` |

Both keys are generated by `image/build.sh` (`secrets/id_backup`, `secrets/id_tunnel`,
ed25519, created once and reused for every image build) and baked into the image.

## What `server/setup-infmk1.sh` does

Idempotent — safe to run again (e.g. for key rotation or after changing ports).

1. Installs `rsync`, `openssh-server`, `python3` if missing.
2. Finds `rrsync`: `/usr/bin/rrsync` (rsync ≥ 3.2.4, Debian 12+/Ubuntu 23.04+), otherwise
   unpacks `/usr/share/doc/rsync/scripts/rrsync.gz` to `/usr/local/bin/rrsync`.
3. Creates system users
   - `projtunnel` — shell `/usr/sbin/nologin`, locked password. The tunnel uses `ssh -N`,
     so no command ever runs.
   - `projbackup` — shell `/bin/sh` (sshd needs a shell to start the forced `rrsync`
     command), locked password.
4. Writes `~/.ssh/authorized_keys` for both (owned by root, so the restricted users
   cannot change them) with the options shown above.
5. Creates the backup root `/srv/theater-projektor/{media,snapshots}` owned by `projbackup`.
   The projector writes `media/`, `show.json` and `snapshots/show-<timestamp>.json` there.
6. Writes `/etc/ssh/sshd_config.d/theater-projektor.conf` with `Match User` blocks:
   `projtunnel` → `AllowTcpForwarding remote`, `GatewayPorts no`, `PermitListen` for the
   two loopback ports, no password / TTY / agent / X11; `projbackup` → no forwarding,
   no password / TTY. The forwarded ports therefore only listen on `127.0.0.1` of infmk1.
7. Runs `sshd -t`, checks the effective settings with `sshd -T -C user=projtunnel,…`
   (forwarding allowed, `GatewayPorts no`, no `DisableForwarding`, warns about
   `AllowUsers`/`AllowGroups`), reloads sshd and prints test commands.

## How to run

`image/build.sh` prints the exact command at the end of each build. In general:

```bash
scp server/setup-infmk1.sh secrets/id_backup.pub secrets/id_tunnel.pub root@infmk1:/root/
ssh root@infmk1 'bash /root/setup-infmk1.sh \
    --backup-key /root/id_backup.pub --tunnel-key /root/id_tunnel.pub \
    --ssh-port 2222 --web-port 8080'
```

Options: `--backup-root DIR` (default `/srv/theater-projektor`). Keys may also be given
as literal strings (`--tunnel-key "ssh-ed25519 AAAA… comment"`).

Then on your PC set `INFMK1_HOST=<hostname of infmk1>` in `secrets/build.env` and
rebuild the image (`image/build.sh --fast`), or on a running projector edit
`/etc/projektor/projektor.toml` (`[backup] host`, `[tunnel] host`, `enabled = true` in
both sections) and `sudo systemctl restart projektor projektor-tunnel`.

The projector accepts infmk1's SSH host key on first contact (`StrictHostKeyChecking
accept-new`). If infmk1 is reachable while building, `build.sh` pins its host keys
into the image with `ssh-keyscan` instead.

## Connect to the projector through the tunnel

Tunnel state on the projector: `/run/projektor/tunnel.json` (`up`, `connecting`,
`down`, `disabled`), also shown on the status screen and in the web UI.

Shell (as admin user `theater`, via your own account on infmk1 as jump host):

```bash
ssh -J you@infmk1 -p 2222 theater@localhost
```

Convenient `~/.ssh/config` entry on your PC:

```
Host projektor-remote
    HostName localhost
    Port 2222
    User theater
    ProxyJump you@infmk1
    # the projector's host key is stored under [localhost]:2222
    HostKeyAlias projektor
```

Web UI: forward a local port to the tunnel's web port, then open
<http://localhost:8080/> in your browser:

```bash
ssh -N -L 8080:localhost:8080 you@infmk1
```

Copy files (e.g. a large video) directly:

```bash
scp -J you@infmk1 -P 2222 film.mp4 theater@localhost:/tmp/
```

## Rotating keys

1. On your PC: move the old keys away and build a new image:
   ```bash
   mkdir -p secrets/old && mv secrets/id_backup* secrets/id_tunnel* secrets/old/
   image/build.sh --fast          # generates new keys, bakes them into the image
   ```
2. Run `setup-infmk1.sh` again with the new `.pub` files (command printed by the build).
   This replaces the keys in `authorized_keys`; the old keys stop working immediately.
3. Flash the new image — or, to rotate on a running projector without reflashing,
   copy the new private keys to `/var/lib/projektor/.ssh/` (owner `projektor`, mode
   `0600`) and `sudo systemctl restart projektor-tunnel`.

To revoke access entirely (lost/stolen projector): on infmk1 empty
`/var/lib/projtunnel/.ssh/authorized_keys` and `/var/lib/projbackup/.ssh/authorized_keys`.

## Troubleshooting

- `journalctl -u projektor-tunnel` on the projector shows the ssh connection log.
- `remote port forwarding failed for listen port 2222`: a stale session still holds the
  port on infmk1 (after a power loss it takes up to ~90 s until sshd notices, thanks to
  `ClientAliveInterval 30`). autossh retries automatically.
- `ss -ltn | grep -E ':(2222|8080)'` on infmk1 shows whether the tunnel is listening.
- Only one projector can use the ports 2222/8080 at a time (single-device design).
